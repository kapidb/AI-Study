dotsは、継続して仕事を進め、結果や判断が必要な点を届けるAIエージェントです。メール、資料、進行中の作業を結びつけ、何から進めるかを相談する窓口として使えます。

02 / KNOWLEDGE

基本の仕組みと、利用できる環境

dotはクラウド上に作業用のコンピューターとブラウザーを持ちます。会話を続けながら仕事を進め、必要なところで結果や確認事項を受け取る形で利用できます。

利用するアカウントでは、dotsの表示、対象プラン、地域、年齢、組織の設定を確認します。提供条件と利用枠は更新されるため、公式のdots概要と実際の画面を照らし合わせます。

仕様の確認日

2026年10月22日に公式情報を確認しています。dotとの会話と、dotが開始・管理するWorkやCodexの作業では、利用量の扱いが異なります。継続して使う際は、実際の作業と残り枠も確認します。

03 / KNOWLEDGE

クラウド・接続アプリ・手元のパソコン

仕事を進める場所と、情報を取得する経路を分けて考えます。どこへ資料があり、どの接続が必要かを整理すると、作業が止まったときも確認しやすくなります。

使う環境仕事の例確認する条件
dotのクラウド環境ウェブ調査、資料の準備、クラウド側で完結する作業を進めます。クラウド側のファイルと、サイトへのサインイン状態を確認します。
接続したアプリメールや保存資料など、認められた情報を参照します。接続アカウント、権限、対応する操作、有効期限を確認します。
接続したパソコン手元のフォルダー、アプリ、ローカルの作業を使います。対象のパソコンをオンラインにし、ChatGPTアプリを開いておきます。

クラウドのブラウザーと、普段使う端末のブラウザーは、それぞれサインイン状態を持ちます。接続の条件は、コンピューターとアプリの公式ガイドで確認できます。

04 / KNOWLEDGE

画面の入り口と、確認する場所

dotのプロフィールを起点に、名前や外観、コンピューター、活動などを確認します。画面の配置はアプリや版によって変わるため、現在使っている環境で確認します。

見る場所確認すること
プロフィールdotの名前、見た目、接続や活動への入り口を確認します。
Computersクラウド環境と、接続したパソコンの状態を確認します。
Activity進行中の作業、成果、追加の確認が必要な点を見ます。
作成された成果物保存先、内容、形式と、必要な確認の結果を見ます。
Scheduled定期的な仕事の内容、時刻、通知先を確認します。

クラウドのコンピューターを自分で操作する場合は、操作を引き継ぐ手順を使います。ログインなどの必要な操作を終えたら、dotへ操作を戻して進めます。

05 / KNOWLEDGE

メールから、期限と返信の準備を整理

メールを整理する使い方では、受信した情報から、返答が必要な案件、約束した期限、決定待ちを見つけます。候補と元メールを一緒に示してもらうと、自分で優先順位を確認できます。

  1. 対象を絞る

    案件、相手、期間など、確認するメールの範囲を決めます。

  2. 要点を取り出す

    約束、期限、未回答、準備する資料を整理します。

  3. 根拠を確認する

    元メールを開き、期限や現在の状況を照合します。

  4. 返信案を用意する

    相手と目的に合わせ、返答や確認の下書きを作ります。

  5. 保存と送信を確認する

    下書きの内容と保存先を確認し、送信する範囲を決めます。

依頼例：今日確認するメール

参照できるメールから、今週の案件で返信が必要なものと、期限が近い約束を整理してください。件名、相手、期限、必要な行動、元メールの参照先を付けてください。重要なものを3件までに絞り、理由を添えてください。返信は下書きを用意するところまで進めてください。

06 / KNOWLEDGE

先回りの提案を、根拠付きの確認へ

dotには、接続したアプリから役立つ情報を調べ、提案へつなげる働きがあります。提案を受け取ったら、根拠の日時と、その後に更新された状況を確かめます。

提示される情報人が確認すること
期限の近い約束確定した日付、対応済みか、変更の連絡があるかを確認します。
返答が必要そうな連絡相手が期待する対応と、別経路のやり取りを確認します。
次に進める作業現在の優先順位、残る前提、準備の負担を確認します。
返信や調整の提案内容、宛先、時期、今回任せた範囲を確認します。

特定の対象を継続して見てほしい場合は、対象と通知条件を依頼します。一定の時刻に繰り返す仕事は、時刻とタイムゾーンを指定し、保存された予定を確認します。

07 / KNOWLEDGE

役割ごとのフォルダーを、仕事の知識に

制作、分析、顧客対応など、役割ごとに資料をまとめると、AIへ渡す背景を整理しやすくなります。役割の説明、過去の判断、実績、進行中の内容を分けて残します。

work-knowledge/
├─ planning/
│  ├─ role.md          企画担当の目的と手順
│  ├─ decisions.md     判断基準と変更の理由
│  └─ projects/        進行中の企画と資料
├─ analysis/
│  ├─ metrics.md       指標・期間・集計条件
│  └─ reports/         実績と分析結果
└─ priorities.md       現在の優先順位

これはフォルダー構成の例です。役割の名前に加え、使う資料、更新日、作業範囲、確認する基準を明記します。AIへ依頼する際は、今回の役割と参照する場所を指定します。

役割を引き継ぐ依頼例

planning内のrole.mdとdecisions.mdを読み、今回の企画を整理してください。現在の優先順位はpriorities.mdです。参照した判断基準と、追加確認が必要な条件を示してください。

08 / KNOWLEDGE

別の端末から、接続したパソコンへ依頼

スマートフォンなどから同じdotへ話しかけ、接続済みのパソコンを使う仕事を依頼できます。相談する端末と、実際にファイルを扱うパソコンの役割を分けると、構成を把握しやすくなります。

役割構成例
相談する端末スマートフォンや別のパソコンから、同じdotへ依頼します。
調整するdot目的を整理し、必要な資料と作業の場所を選びます。
接続したパソコン許可した範囲で、資料の読み取りや作業を進めます。
結果の受け取り元の相談へ、成果と確認事項をまとめてもらいます。

2026年10月22日時点の公式案内では、接続する個人のパソコンは一度に1台です。ローカルの作業中は、対象端末のオンライン状態とアプリの起動を維持します。

同期フォルダーを使う場合

必要なファイルが接続先で読める状態かを確かめます。ファイルの同期、端末の接続、dotへのアクセス許可をそれぞれ確認し、使う資料の最新版を指定します。

09 / KNOWLEDGE

依頼を、実行する仕事へ組み立てる

dotは、必要な仕事をタスクへ分け、結果をまとめる進め方を取れます。利用者は目的と完成の形を伝え、タスクへ渡す資料や条件が揃っているかを確認します。

  1. 目的を受け取る

    何を決めたいか、どの成果が必要かを整理します。

  2. 必要な資料を選ぶ

    参照先、期間、判断基準を指定します。

  3. 作業を分ける

    調査、集計、制作などの仕事へ、必要な条件を渡します。

  4. 途中の情報を補う

    不足した条件や、新しく分かったことを反映します。

  5. 結果をまとめる

    長い出力から、結論、根拠、次の行動、確認事項を整理します。

タスクごとの会話には、その仕事用の指示と情報が渡ります。重要な前提を共有する方法と、元資料の場所を明示すると、確認を進めやすくなります。詳しくは作業と記憶の公式ガイドを参照できます。

10 / KNOWLEDGE

実践例：企画資料から、次の行動を選ぶ

複数の企画と下書きがある場合は、進行状況と今の優先順位を踏まえて、次の行動を選んでもらいます。資料の紹介に加えて、実行できる単位へ整理することがポイントです。

依頼例：次に進める企画

企画フォルダーと現在の優先順位を参照し、今取り組むとよさそうな行動を2〜3点に絞ってください。各案に、選んだ理由、参照した資料、最初に行う作業、必要な確認を付けてください。期限や約束に影響する場合は、その根拠も示してください。

確認する材料提案へ反映すること
企画の一覧候補の全体と、重複する内容を整理します。
台本や下書き完成までの残り作業を把握します。
判断の記録対象者、表現、採用する条件を合わせます。
期限と依頼外部との約束、確認待ち、順序を整理します。

提案を受け取った後は、今の予定と照らして実行するものを選びます。追加の作業を任せる際は、その範囲と完成の目安を伝えます。

11 / KNOWLEDGE

音声通話で、短い相談と依頼

音声でのやり取りは、移動中や手元で入力しづらい場面の相談に使えます。たとえば優先順位を聞き、調査を依頼し、結果を受けて次の作業を選ぶ使い方が考えられます。

音声での依頼例

今の案件で、今日確認することを3つに絞って教えてください。その後、指定した資料から直近の実績を整理してください。結果は、期間、主な変化、確認する点の順で、文章にも残してください。

  • 対象の案件、資料、期間を、短い言葉で明確に伝えます。
  • 会話の途中で依頼を加える際は、先の作業も続けるかを伝えます。
  • 重要な数値や条件は、文字の結果と元資料で確認します。
  • 接続状況や応答を見ながら、必要に応じてテキストへ切り替えます。

利用できる連絡方法と通話の説明は、公式のメッセージ・通話ガイドで確認できます。

12 / KNOWLEDGE

会話で頼む分析も、数値と期間を確認

実績データを使う仕事では、会話の自然さに加えて、集計の前提を揃えます。期間、集計対象、指標の定義を確認してから、変化と次の検討へ進みます。

確認する項目実績分析での例
データの対象全体の実績と、個別の成果物の実績を分けます。
期間開始日、終了日、途中までの月を明記します。
指標増加数、累計、率など、比較する値を揃えます。
解釈確認した事実と、変化の理由に関する仮説を分けます。
次の行動追加で調べることと、小さく試す改善を整理します。

分析の結果は、参照ファイルと一緒に保存します。音声で受け取った数字も、文章や表に残すと後から照合しやすくなります。

13 / KNOWLEDGE

活動・権限・成果を、確認できる形に

任せた仕事は、Activityから進捗や成果を開いて確認します。資料を読める範囲、下書きを作る範囲、外部へ送る範囲を、依頼の中でも具体化します。

段階確認すること
参照どのアカウントの、どの資料を読むかを確認します。
作成何を作り、どこへ保存するかを確認します。
変更更新する対象と、元の状態への影響を確認します。
送信や共有宛先、内容、時期、必要な承認を確認します。
受け取り保存された成果物と、実施した検証を確かめます。

既存の権限と組み込みの確認は、継続的な依頼にも適用されます。具体的な管理方法は、dotの制御と確認の公式ガイドを参照できます。

進捗を確かめる依頼例

いま確認できた資料、完了した作業、進行中の作業、私の判断を待っている点を分けて教えてください。完成物の保存先と、確認した項目も示してください。

14 / KNOWLEDGE

仕事を頼むための、準備と調整を支える

複数のAIや資料を使うと、依頼先を選び、背景を渡し、途中の結果を確認する作業も増えます。dotを相談窓口にすると、その調整をまとめて任せる使い方が考えられます。

相談の入口

「次に何を進めるか」という段階から相談します。

役割ごとの知識

育ててきた資料と判断基準を、必要な作業へ渡します。

作業の実行

選んだ環境で処理し、進捗と結果を確認します。

意思決定

次の行動と判断が必要な点を、分かりやすく受け取ります。

効果は、作業の速さに加え、依頼を組み立てる時間、確認の往復、対応の抜けを含めて見ます。役割ごとの資料と、優先順位の更新を続けることが運用を支えます。

  6. 成果と手間を振り返る

    内容、保存先、確認時間、役立った点を見て、次の範囲を決めます。
